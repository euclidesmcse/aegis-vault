## Shim roundtrip - lista dos 7 testes (titulos literais)

Os 7 testes em `packages/crypto/test/shim-roundtrip.test.mjs` (titulos abaixo sao os mesmos que `await t(...)` imprime em verde PASS) exercitam, sob o libsodium shim:

1. `aead: encrypt then decrypt recovers plaintext of mixed sizes` - 3 tamanhos (1B, 10B, 1024B).
2. `envelope: encrypt then decrypt with matching AAD recovers plaintext` - happy path.
3. `envelope: changes in AAD tenantId cause aad-mismatch (refuses to decrypt)` - sad path (lanca erro `aad mismatch`).
4. `envelope: buildAad is deterministic + version-mutation shifts bytes` - determinismo + efeitos do campo `version` no AAD.
5. `share: createShare then revealShare with full payload recovers plaintext` - happy path.
6. `share: revealShare with a wrong token refuses to decrypt (AEAD tag mismatch)` - sad (token arbitrario gera tag mismatch GCM) + recovery com token correto.
7. `export: .aegis round-trips when exportedAt is pinned via Date mock` - round-trip total; contem o regression check `tail.length > 0 && tail.every(b => b === 0)` que captura re-introducao do bug de over-alocacao.

### Fix binario em `packages/crypto/src/export.ts`

Bug concreto: o writer em `createExportBundle()` alocava `magic + 1 + salt + NONCE_BYTES + sealed.length` (24 bytes a mais do que o necessario) e DEPOIS escrevia o buffer `sealed` de duas formas no mesmo offset 25: primeiro via `file.set(nonce, off)` com `nonce = sealed.slice(0, NONCE_BYTES)` (= os primeiros 24 bytes do buffer = `npub`), e segundo implicitamente porque `aead.ts::encrypt` ja devolve `npub || ct_with_tag`. Resultado no file em disco: bytes [25..49] continham o `npub` duplicado, bytes [49..(49 + sealed.length - 24)] continham o `ct_with_tag` verdadeiro, e os 24 bytes finais (over-alocacao) ficavam zerados.

No read, o leitor reconstituia `sealed2 = nonce || ct_slice_from_49` = `npub || (ct_with_tag + 24_zero_bytes)`. Sob shim (AES-GCM), o GCM auth-tag e lido nos ULTIMOS 16 bytes do input - caia sobre os zeros impostos, nao sobre os bytes de tag reais. Resultado: `subtle.decrypt` lanca `OperationError: The operation failed for an operation-specific reason` (no real libsodium, o resultado seria lixo - o texto nao protege por si).

Fix: alocar exatamente `magic + 1 + salt + sealed.length` e escrever `file.set(sealed, off)` uma unica vez apos o salt. O reader slicing em offsets fixos continua correto: bytes [25..49] = `npub`, bytes [49..end] = `ct_with_tag`.

`shim-roundtrip.test.mjs` contem o regression check `tail.length > 0 && tail.every(b => b === 0)` (mensagem: `regression: file tail bytes are all zero (over-allocation bug)`) que falha se os ultimos 24 bytes do file forem todos zero.

**Impacto de compatibilidade binaria:** arquivos `.aegis` antigos (escritos pelo writer buggy) NAO sao decifraveis pelo reader corrigido (forward-fix sem backward-compat). Operadores devem purgar caches locais de exports antes de upgrade.
